# Alpaca Paper 组合绩效接入设计

**日期：** 2026-08-11
**状态：** 已确认，待实施

## 1. 目标

让 Alpaca Paper 组合页面基于券商账本和真实历史行情展示可追溯的组合绩效，包括收益曲线、SPY 基准、区间指标、回撤和绩效归因。Paper 数据必须与手工组合隔离；存在未解决的券商对账漂移时，不展示可信绩效。

## 2. 范围

本阶段包含：

- 从 `/api/v1/portfolio/alpaca-paper/ledger` 加载类型化 Paper 账本。
- 将 Broker Decimal 字符串和券商事件语义适配为现有绩效引擎的输入。
- 用现有市场 API 加载持仓历史日线、SPY 复权基准日线和拆股事件。
- 在 Paper 组合中提供“总览 / 绩效 / 订单”三个页面区域。
- 复用现有绩效摘要、收益曲线、现金流和归因展示。
- 覆盖加载、空账本、数据降级、对账漂移和刷新状态。

本阶段不包含：

- Live Trading 或 Live 账户。
- 将 Paper 数据写入手工组合账本或手工组合设置。
- Paper 组合的自定义基准持久化。
- 在 Paper 绩效页确认手工拆股、编辑初始资金或记录手工现金流。
- 服务端重复实现现有客户端绩效算法。

## 3. 架构选择

采用“客户端适配 + 复用现有绩效引擎”。服务端继续负责券商原始事实、账本、订单和对账状态；浏览器负责加载账本与市场历史，并调用现有 `PerformanceHistoryLoader`、`calculatePerformance` 和 `calculateAttribution`。

不新增服务端绩效聚合接口。这样可以保持手工组合与 Paper 组合共用同一套收益、基准和归因口径，同时避免在两个运行时复制计算逻辑。

## 4. 模块边界

### 4.1 Paper Portfolio API

`paperPortfolioApiClient.ts` 新增明确的 `PaperLedgerEventView` 类型和 `listLedger()` 方法。API 保留数据库中的 Decimal 字符串，不在传输边界提前转换为 JavaScript `number`。

账本事件至少包含：

- `id`
- `remoteSourceId`
- `eventType`
- `symbol`
- `quantity`
- `price`
- `amount`
- `occurredAt`
- `provenanceJson`

### 4.2 Broker Performance Adapter

`brokerPerformanceAdapter.ts` 是 Paper 账本进入现有绩效领域的唯一转换边界。它负责：

- 拒绝任何非 `alpaca-paper` 来源。
- 忽略 `unknown` 事件并产生明确提示。
- 将买入、卖出、分红、费用、入金、出金和拆股映射为 `LedgerEvent`。
- 将费用和出金规范化为正的绝对金额；分红和入金同样使用正金额。
- 保留券商事件 ID、发生时间和来源标识，保证排序稳定且可追溯。
- 对缺少必需字段或无法解析的 Decimal 值返回不可用状态，不静默制造零值。
- 在存在活动对账漂移时返回 `unavailable`，且不把事件交给绩效引擎。

Decimal 只在适配器的最终计算边界转换为现有引擎所需的有限 `number`。券商活动入口的精确金额乘法由后续“金额精度加固”工作独立处理。

### 4.3 Paper Performance Controller

新增 Paper 专用绩效控制组件，职责为：

1. 加载 Paper overview 和 ledger。
2. 用 SPY、`initialCash = 0` 以及最早账本日期构造只读绩效设置。
3. 调用现有 `usePortfolioPerformance` 加载行情并计算结果。
4. 支持成立以来、年初至今、1 年、6 个月、3 个月和自定义区间。
5. 在用户刷新时重新加载券商账本和历史行情。
6. 将错误、陈旧数据和来源时间传给展示层。

`initialCash = 0` 的前提是 Paper 账本包含券商现金活动。若账本有交易但没有足够的现金起点，组件显示“Paper 现金历史不足”，不把结果标记为可信。

### 4.4 共享绩效展示

`PortfolioPerformanceTab` 增加只读能力配置，使 Paper 页面能够：

- 显示范围选择、SPY 基准、摘要、曲线、现金流和归因。
- 隐藏组合设置、自定义基准、手工拆股确认和手工现金流入口。
- 保留刷新按钮和数据状态提示。

手工组合现有行为保持不变。

### 4.5 Paper 页面结构

`PaperPortfolioOverview` 提供三个互斥页面区域：

- **总览：** 账户指标、持仓、对账提示和重新对账。
- **绩效：** Paper 专用绩效控制组件及只读绩效展示。
- **订单：** 现有订单历史；完整订单操作将在下一阶段增强。

Order Ticket 保留在总览区域。存在 drift 时继续禁止提交订单，绩效区域同时显示不可用原因。

## 5. 数据流

1. 页面加载 Paper overview，取得账户、持仓、`asOf` 和活动 drift。
2. 用户打开“绩效”后加载 Paper ledger。
3. Adapter 校验来源、字段、金额符号和现金历史完整性。
4. 从适配后的账本提取曾持有股票与成立日期。
5. `PerformanceHistoryLoader` 批量请求原始持仓日线、SPY 复权日线和市场事件。
6. 现有绩效引擎计算每日估值、TWR、MWR、基准、超额收益和回撤。
7. 现有归因引擎计算标的、分红和费用贡献并执行金额对账。
8. 页面展示结果、来源时间、降级提示或明确的不可用原因。

## 6. 错误与降级

- **活动 drift：** 不加载或不展示可信绩效，提示“Paper 对账不一致”。
- **账本请求失败：** 展示账本加载失败；不得退回手工组合事件。
- **账本为空：** 展示“暂无 Paper 成交与现金活动”，不生成虚构曲线。
- **现金历史不足：** 绩效不可用并说明必须先完成全量活动对账。
- **持仓历史行情失败：** 按现有引擎规则标记不可用；可显示上次缓存但必须标记陈旧。
- **SPY 基准失败：** 组合收益仍可展示，基准与超额收益显示不可用。
- **拆股事件失败：** 保留绩效结果并提示无法验证拆股；Paper 页面不允许手工确认。
- **无效 Decimal：** 整体适配失败，错误包含事件 ID，不把无效字段当作零。

## 7. 测试策略

### 7.1 单元测试

- API Client 正确请求 Paper ledger。
- Adapter 覆盖全部支持事件、金额符号、稳定 ID、无效 Decimal、未知事件和 drift。
- Paper 绩效控制器用 `initialCash = 0`、最早事件日期和 SPY 构造输入。
- 无现金起点、空账本和账本加载失败产生明确状态。
- 只读绩效模式隐藏手工组合控制，但不改变手工组合行为。

### 7.2 组件测试

- Paper 页面可在总览、绩效和订单之间切换。
- 绩效页展示收益摘要、SPY 曲线和归因。
- drift 时显示不可用提示且不展示可信指标。
- 刷新会重新读取账本并重新计算。

### 7.3 端到端测试

Fixture 流程创建 Paper 成交并运行 reconciliation 后，浏览器打开 Paper 绩效页，验证：

- 成交与现金活动出现在绩效计算中。
- 页面显示组合收益、SPY 基准和贡献对账。
- 注入 drift 后绩效被隐藏并显示原因。
- 清除 drift 并刷新后绩效恢复。

## 8. 完成标准

- Paper 页面从 Broker ledger 和市场 API 计算绩效，不读取手工组合账本。
- 收益曲线、基准、回撤和归因可以从浏览器访问。
- drift、空账本、现金历史不足和行情失败均有可验证的明确状态。
- 手工组合现有绩效功能与测试保持通过。
- 相关单元测试、组件测试、E2E 和生产构建全部通过。
