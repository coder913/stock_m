# 券商金额定点精度设计

## 目标

消除 Alpaca 成交活动进入 Paper 账本时的 JavaScript 浮点乘法，使数量、价格、成交金额、账本回放与对账差额在服务端始终使用与 PostgreSQL `numeric(28,8)` 一致的八位定点表示。

## Decimal 规则

- 输入是普通十进制字符串，可带负号，整数部分必须存在，小数最多 8 位。
- 内部表示为缩放 `100000000` 的 BigInt。
- 输出始终包含 8 位小数，避免科学计数法与平台相关格式。
- 乘法将两个八位定点值相乘，再按“绝对值五入”舍入回 8 位；正负值采用对称规则。
- 非法格式、超过 8 位小数和负的成交数量/价格直接抛出明确错误，不静默截断。

## 活动映射

- 若 Alpaca 活动已提供 `amount`，保留原始 Decimal 字符串交给数据库约束。
- 若 FILL 缺少 `amount`，使用 BigInt 定点数量乘价格。
- buy 生成负金额，sell 生成正金额；先取乘积绝对值，避免异常负输入改变现金方向。
- 未知活动仍只保留 provenance，不虚构金额。

## 账本复用

`brokerLedger` 改用相同 Decimal 解析、格式化和减法函数。这样入口计算、数据库八位 Decimal、回放与 drift 差额共享一套精度和验证规则。

订单预览已有独立的领域错误码与正数校验，本次不改变其 API 错误语义；后续可在保持错误映射的前提下复用底层工具。

## 测试

- `0.1 × 0.2` 不出现二进制浮点尾差。
- 超过 JavaScript 安全整数范围的数量仍保留精确金额。
- 半个最小单位按规则舍入。
- buy/sell 符号正确。
- 非法或超出 8 位的小数被拒绝。
- 现有账本回放和 drift 差额测试保持通过。
