# stock_m 持仓与复盘子系统设计规格

日期：2026-08-06
状态：已确认，待实施计划

## 1. 目标

为个人美股投资者建立从模拟交易、持仓计算、组合风险识别、应用内提醒到每周复盘的完整闭环。

> 交易记账 → 持仓与盈亏 → 暴露和风险规则 → 应用内提醒 → 处理与复盘 → 周度快照 → 下一周期观察

首期继续使用确定性模拟价格和本地存储，不连接真实券商、不发送真实订单、不提供外部通知，也不生成自动买卖建议。

## 2. 范围

### 2.1 包含

- 不可变模拟交易账本。
- 买入、卖出、分红和费用事件。
- 当前持仓、现金、平均成本和盈亏计算。
- 单股权重、行业暴露、前五大持仓集中度和最大回撤。
- 应用内风险提醒、确认、暂缓和关闭。
- 事件触发检查和每周复盘。
- 不可变组合快照、复盘版本和版本差异。
- 现有 `stock_m:orders` 模拟订单的一次性迁移。

### 2.2 不包含

- 真实券商账户连接和订单路由。
- 自动调仓、止损或买卖执行。
- 邮件、短信、推送和浏览器系统通知。
- 税务批次、洗售规则和报税计算。
- 多币种、期权、保证金和做空。
- 用户自定义规则编辑器。
- 基于黑盒模型的组合评分或投资建议。

## 3. 产品结构

“组合”一级入口包含三个标签：

| 标签 | 职责 |
| --- | --- |
| 组合总览 | 总资产、现金、盈亏、净值曲线、回撤、集中度和行业暴露 |
| 持仓与交易 | 当前持仓、交易账本以及买入、卖出、分红和费用录入 |
| 复盘中心 | 应用内提醒、待复盘事项、每周复盘和历史版本 |

现有“日志”入口展示跨组合的复盘历史和投资逻辑记录；组合页负责当前组合的操作和分析。

## 4. 核心用户流程

### 4.1 交易与持仓

1. 用户从研究页或组合页发起模拟交易。
2. 买入必须关联投资逻辑版本；卖出必须关联逻辑版本或填写调整原因。
3. 系统向账本追加不可变事件。
4. 分析层使用账本、初始现金和当前价格重新计算持仓与组合指标。
5. 风险引擎检查新状态并生成或更新提醒。

### 4.2 提醒处理

1. 事件触发时执行风险检查；应用打开时恢复到期的暂缓提醒。
2. 用户查看提醒的规则、阈值、当前值和计算时间。
3. 用户可以确认、关闭或暂缓至指定日期。
4. 处理提醒时可创建复盘记录，填写判断、行动、结果和下一观察点。

### 4.3 每周复盘

1. 系统汇总本周期资产变化、主要贡献者、交易、现金流和提醒变化。
2. 用户补充逻辑偏差、经验和下周期计划。
3. 提交后保存不可变组合快照和复盘版本。
4. 同一周再次提交时创建新版本，并显示与上一版本的差异。
5. 无交易周期也允许生成“无操作复盘”。

## 5. 领域模型

```ts
type LedgerEventType = "buy" | "sell" | "dividend" | "fee";

interface LedgerEvent {
  id: string;
  type: LedgerEventType;
  symbol?: string;
  occurredAt: string;
  quantity?: number;
  price?: number;
  amount?: number;
  thesisVersionId?: string;
  reason?: string;
}

interface PositionSnapshot {
  symbol: string;
  quantity: number;
  averageCost: number;
  marketPrice?: number;
  marketValue?: number;
  realizedPnl: number;
  unrealizedPnl?: number;
  weight?: number;
  sector: string;
}

interface PortfolioSnapshot {
  id: string;
  asOf: string;
  positions: PositionSnapshot[];
  cash: number;
  totalValue?: number;
  cumulativePnl?: number;
  drawdownPercent?: number;
  sectorExposure: Record<string, number>;
}

interface PortfolioAlert {
  id: string;
  dedupeKey: string;
  rule: string;
  severity: "info" | "warning" | "critical";
  symbol?: string;
  message: string;
  currentValue: number | string;
  threshold: number | string;
  status: "open" | "snoozed" | "resolved";
  createdAt: string;
  snoozedUntil?: string;
  resolvedAt?: string;
}

interface WeeklyReview {
  id: string;
  week: string;
  version: number;
  snapshotId: string;
  judgment: string;
  action: string;
  result: string;
  nextObservations: string[];
  createdAt: string;
}
```

所有时间使用 ISO 8601 字符串，金额以 USD 计价。缺失价格使用 `undefined`，不得转换为零。

## 6. 模块边界

| 模块 | 职责 | 依赖 |
| --- | --- | --- |
| PortfolioLedger | 账本追加、查询、验证和旧订单迁移 | 版本化本地存储 |
| PortfolioAnalytics | 持仓、成本、盈亏、暴露、集中度和回撤纯函数计算 | 账本、价格和股票行业目录 |
| AlertEngine | 确定性规则、去重、到期恢复和提醒状态转换 | 分析结果、公司事件和投资逻辑 |
| AlertRepository | 提醒持久化和最后成功计算状态 | 版本化本地存储 |
| ReviewRepository | 复盘、快照和版本持久化 | 版本化本地存储 |
| PortfolioPage | 总览、持仓交易和复盘中心编排 | 上述领域模块 |

页面不得直接解析存储数据。计算函数不得读写浏览器 API。未来账户 API 只替换账本、价格和仓储适配器。

## 7. 账本与迁移规则

- 账本事件只追加，不在原记录上修改。
- 交易修正通过追加冲销事件和正确事件完成；首期 UI 不提供手工冲销入口。
- 买入增加数量和成本；部分卖出按移动加权平均成本计算已实现盈亏。
- 分红增加现金和累计盈亏，不改变持仓成本。
- 费用减少现金和累计盈亏。
- 卖出数量超过当前持仓时拒绝事件并返回可卖数量。
- 买入和卖出的数量、价格必须大于零；分红和费用金额必须大于零。
- 现有 `stock_m:orders` 首次迁移为 `buy` 事件，保留原 `thesisVersionId`。
- 迁移成功后写入版本标记；重复初始化不得产生重复事件。
- 账本存储键为 `stock_m:portfolio-ledger:v1`。

## 8. 组合分析

首期计算：

- 现金、总市值和总资产。
- 已实现、未实现、当日和累计盈亏。
- 持仓数量、移动加权平均成本和持仓权重。
- 单股权重、行业暴露和前五大持仓集中度。
- 基于历史周度快照净值的当前回撤和最大回撤。
- 净值曲线、盈亏贡献和风险贡献的表格与图形。

缺失价格时保留持仓数量、成本和已实现盈亏；市场价值、权重、未实现盈亏和依赖总资产的指标显示“估值不可用”。如果任一持仓价格缺失，不显示伪精确的组合总值。

## 9. 默认提醒规则

| 规则 | 警告 | 严重 |
| --- | --- | --- |
| 单股仓位 | 达到 20% | 达到 30% |
| 单一行业暴露 | 达到 35% | 达到 45% |
| 组合从历史高点回撤 | 达到 10% | 达到 15% |
| 财报前未更新投资逻辑 | 7 天内 | 不适用 |
| 投资逻辑验证条件到期或失效 | 不适用 | 立即 |

无逻辑关联的卖出、分红或费用生成信息提醒，要求补充调整原因。提醒去重键由“规则 + 股票或组合 + 自然周期”组成。同一问题只保留一条活动提醒；严重程度上升时更新活动提醒。关闭后的相同问题只在下一自然周期重新创建。

首期阈值固定，并在提醒中显示规则、阈值、当前值、数据来源和计算时间。

## 10. 页面行为

### 10.1 组合总览

- 顶部指标卡显示总资产、现金、当日盈亏、累计盈亏、最大回撤和集中度。
- 净值曲线支持组合净值与基准归一化比较，首期基准使用 SPY 模拟序列。
- 行业暴露同时显示百分比、数值标签和方向，不只依赖颜色。
- 风险贡献按绝对影响排序，不生成黑盒综合分数。

### 10.2 持仓与交易

- 持仓表显示代码、数量、平均成本、价格、市值、权重、已实现和未实现盈亏。
- 行操作提供买入、卖出和进入研究页。
- 交易表单根据事件类型显示数量、价格或金额字段。
- 卖出表单实时显示可卖数量；错误定位到具体字段。
- 交易历史按时间倒序，并明确显示逻辑版本或调整原因。

### 10.3 复盘中心

- 提醒按严重、警告、提示排序，并可按状态筛选。
- 暂缓提醒必须选择恢复日期。
- 周报生成器自动带入组合变化、交易和提醒摘要。
- 用户填写判断、行动、结果和下一观察点后提交。
- 历史周报显示周次、版本、提交时间和差异摘要。

## 11. 空白与异常状态

- 无交易时展示首笔模拟买入入口。
- 无提醒时展示“当前没有待处理风险”，不隐藏规则检查时间。
- 无交易周允许提交无操作复盘。
- 缺失价格显示“估值不可用”，不使用零值。
- 卖出超量时阻止提交并显示可卖数量。
- 账本 JSON 损坏时停止分析，提供原始字符串下载，不静默重置。
- 提醒计算失败时保留上次成功结果，并显示更新时间和过期状态。
- 本地存储写入失败时保留交易或复盘草稿，并提供重试按钮。
- 同一周重复提交复盘时自动创建递增版本。

## 12. 可访问性与响应式

- 指标卡、图形和表格提供文本等价信息。
- 表格使用正确的表头、排序状态和带股票代码的行操作标签。
- 提醒严重程度同时使用文字和图标，不只依赖颜色。
- 所有表单、标签页、对话框和提醒操作可使用键盘。
- 焦点样式满足 WCAG 2.2 AA。
- 1440 px 显示总览图形与侧栏提醒。
- 1280 px 将提醒移至总览下方。
- 1024 px 将持仓次要列折叠进详情，交易表单使用抽屉。

## 13. 测试与验收

### 13.1 单元测试

- 旧订单迁移只执行一次。
- 买入、追加买入、部分卖出、全部卖出和卖出超量。
- 移动加权平均成本、已实现盈亏、分红、费用和现金。
- 缺失价格、行业暴露、集中度、回撤和最大回撤。
- 所有提醒阈值边界、严重程度升级、去重、暂缓、到期恢复和关闭。
- 周报版本递增、快照不可变和版本差异。

### 13.2 交互测试

- 交易类型切换显示正确字段并验证输入。
- 卖出超量显示可卖数量且不写入账本。
- 提醒确认、暂缓和关闭后状态正确。
- 周报自动填入摘要，保存失败保留草稿。
- 缺失价格时页面显示估值不可用。

### 13.3 端到端测试

- 研究页保存投资逻辑 → 模拟买入 → 组合页查看持仓和暴露。
- 追加交易触发单股仓位提醒 → 打开复盘中心 → 处理提醒。
- 提交每周复盘 → 打开历史版本 → 查看快照和差异。

### 13.4 完成标准

- 所有持仓均可由不可变账本事件确定性重建。
- 组合总览展示可解释的盈亏、集中度、行业暴露和回撤。
- 默认提醒规则在阈值边界产生正确且不重复的提醒。
- 用户可以完成提醒处理和每周复盘闭环。
- 旧模拟订单无重复、无丢失地迁移。
- 单元、交互、构建和 Chrome 端到端测试通过。
