# Paper 订单历史与撤单交互设计

## 目标

让 Alpaca Paper 组合页中的订单标签成为可操作、可追溯的订单控制面：用户能查看订单完整字段和事件时间线，对仍可撤销的订单发起幂等撤单，并在无需手动刷新页面的情况下看到状态收敛。

## 交互

- 页面首次加载订单，并每 5 秒重新拉取订单列表。
- 点击“查看详情”展开单个订单；展开时拉取其时间线，后续轮询同时刷新已展开订单的时间线。
- 详情展示订单类型、有效期、限价、客户端订单号、远端订单号、确认时间和更新时间。
- 时间线按服务端顺序展示事件时间、事件类型与关键成交信息。部分成交、撤单请求、最终成交、撤销、拒绝和过期必须同时保留，不以最终状态覆盖历史事件。
- `accepted`、`new`、`partially_filled` 状态可撤单；点击后调用撤单意图接口并立即刷新列表和时间线。
- 撤单请求期间禁用按钮并显示“正在撤单”；服务端状态进入 `cancel_pending` 后不再允许重复撤单。
- 加载失败显示可读错误和重试按钮；轮询失败保留最后一次成功数据。

## 数据与 API

- 扩展 `PaperOrderView` 为服务端订单投影视图的完整类型。
- 新增 `PaperOrderTimelineEventView`，保留结构化 `payloadJson`，并从常见远端事件载荷中提取成交数量、成交均价等摘要。
- `PaperPortfolioApi.cancelOrder(orderIntentId, idempotencyKey)` 调用既有 `/broker/alpaca-paper/cancel-intents`。
- 每次用户撤单生成新的幂等键；同一次按钮操作只发送一次请求。

## 可靠性与可访问性

- 轮询 effect 在卸载和 API 实例变化时清理定时器，并忽略已失效请求的结果。
- 详情按钮通过 `aria-expanded` 表达状态；时间线使用有序列表和标准 `time` 元素。
- 终态订单不渲染撤单按钮，避免产生无意义命令。

## 测试

- API 客户端测试验证撤单路径、请求体和幂等键。
- 组件测试验证详情字段、完整时间线、可撤状态、撤单后刷新、终态禁用规则、自动轮询和失败重试。
- 第 6 项再补浏览器端从页面下单到撤单和成交竞态的完整 E2E。
