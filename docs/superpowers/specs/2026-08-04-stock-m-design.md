# stock_m 产品与体验设计规格

日期：2026-08-04

状态：已确认

产品形态：桌面端 Web 应用

首版定位：面向个人美股投资者的研究、选股、组合跟踪与模拟决策工作台

## 1. 产品摘要

stock_m 帮助个人投资者把分散的行情、财务、事件与投资笔记整理成一条可追踪的决策链：

> 发现变化 → 研究证据 → 记录判断 → 模拟持仓 → 持续验证 → 复盘结果

产品不以“提供更多数据”为目标，而是优先回答三个问题：

1. 今天我关注的股票发生了什么？
2. 哪些证据支持或反驳我的投资判断？
3. 做出模拟决策后，什么条件会要求我重新评估？

首版不接入真实券商，不提供自动买卖建议，也不把 AI 作为荐股工具。

## 2. 目标用户与使用场景

### 2.1 主要用户

- 已经投资或准备投资美股的个人投资者。
- 以基本面和中期趋势为主，偶尔参考技术走势。
- 同时关注约 10–50 只股票，持有约 5–20 个模拟仓位。
- 当前在行情网站、财报网站、新闻应用与笔记工具之间反复切换。

### 2.2 核心场景

- 开盘前或收盘后，用 5 分钟检查自选股的重要变化。
- 发现候选股票后，在一个页面完成价格、财务、估值、同业和事件研究。
- 写下核心判断、证据、风险与验证条件。
- 将股票加入观察或模拟组合，并设置价格、事件或逻辑验证提醒。
- 财报或关键事件发生后，对原判断进行复盘。

### 2.3 成功标准

首版成功不以交易频次衡量，而以决策流程是否闭环衡量：

- 新用户能在 10 分钟内建立自选列表并完成第一条投资逻辑。
- 用户从首页信号进入研究页的路径不超过一次点击。
- 每个模拟持仓都能关联一条投资逻辑和至少一个验证条件。
- 用户能清楚区分实时、延迟、估算和模拟数据。
- 核心任务在 1440 × 1024 视口内无需横向滚动。

## 3. 竞品参考与产品取舍

### 3.1 借鉴

- TradingView：借鉴图表、自选、提醒与市场上下文之间的联动。
- Finviz：借鉴基本面与技术面组合筛选的效率。
- Seeking Alpha：借鉴组合健康提示、评级变化与风险提醒的表达。
- OpenBB：借鉴数据源可替换、研究模块可扩展的系统边界。
- OpenTerminalUI：借鉴工作区与模块化能力，但不复制其首屏功能密度。

### 3.2 差异化

stock_m 的差异化不是更专业的图表，也不是更多指标，而是把“信号、证据、判断、条件和复盘”连接起来。每条信号必须可解释，每条投资逻辑必须可验证，每个模拟仓位必须可追溯。

## 4. 产品原则

1. **决策优先于数据。** 页面先给出值得关注的变化，再提供证据下钻。
2. **解释优先于评分。** 不展示无法说明来源和计算方式的黑盒分数。
3. **研究与交易分离。** 首版所有组合与交易操作均为模拟。
4. **观点必须可验证。** 投资逻辑必须包含判断、证据、风险和验证条件。
5. **时间与来源透明。** 行情延迟、财务周期、数据来源和更新时间始终可见。
6. **AI 只做助手。** AI 可以摘要、比较和检查逻辑，不直接输出买入或卖出结论。

## 5. 首版范围

### 5.1 必须包含

- 延迟行情、指数概览与基础 K 线。
- 美股代码/公司搜索。
- 自选列表、分组与重要变化提示。
- 基本面和技术面条件筛选。
- 股票研究页：概览、图表、财务、估值、同业、事件和投资逻辑。
- 模拟组合、持仓收益、行业暴露和基准比较。
- 决策日志和投资逻辑版本历史。
- 价格、财报、公司事件与验证条件提醒。

### 5.2 明确不包含

- 真实券商连接、真实下单与资金转账。
- Level 2 盘口、高频交易工具和订单流分析。
- 期权链、期权策略与 Greeks。
- 策略回测、自动交易与机器人交易。
- 社交社区、跟单、荐股排行和收益榜。
- AI 自动生成买卖信号。

## 6. 信息架构

### 6.1 一级导航

| 导航 | 用户问题 | 核心内容 |
| --- | --- | --- |
| 今日 | 今天哪些变化值得我关注？ | 市场脉冲、自选信号、本周事件、投资逻辑检查 |
| 发现 | 市场中有哪些候选股票？ | 条件筛选、主题榜单、市场热力图、已保存筛选 |
| 自选 | 我关注的股票发生了什么？ | 分组列表、关键指标、事件、提醒和快速比较 |
| 组合 | 我的模拟决策表现如何？ | 模拟持仓、收益归因、风险暴露、基准比较 |
| 日志 | 当时为什么做出这个判断？ | 投资逻辑、模拟交易记录、提醒结果和复盘 |

全局顶部区域提供股票搜索、数据更新时间、通知和用户菜单。

### 6.2 股票研究页

任意股票统一进入同一个研究工作区，页内导航依次为：

1. 概览
2. 图表
3. 财务
4. 估值
5. 同业
6. 事件
7. 投资逻辑

页面顶部始终保留公司名称、代码、价格、涨跌、数据时间、自选状态和“记录观点”动作。

## 7. 核心用户流程

### 7.1 每日检查

1. 用户进入“今日”。
2. 查看 SPY、QQQ、DIA、VIX 的紧凑市场脉冲。
3. 浏览按相关性排序的自选信号。
4. 展开一个信号，阅读变化原因、图表和相关事件。
5. 进入股票研究页，或将其加入观察。

### 7.2 建立投资逻辑

1. 用户从搜索、筛选器或自选列表进入股票研究页。
2. 查看财务趋势、估值区间、同业比较和近期事件。
3. 创建投资逻辑，填写核心判断、支撑证据、主要风险和验证条件。
4. 选择加入观察或模拟组合。
5. 系统为验证条件建立提醒，并保留逻辑版本。

### 7.3 事件后复盘

1. 财报、价格或验证条件触发提醒。
2. 用户打开对应投资逻辑，比较原判断与新证据。
3. 用户选择“维持、修正或失效”，并填写原因。
4. 系统保存新版本并关联模拟持仓变化。

## 8. 页面设计

### 8.1 “今日”首页

首页采用已确认的融合视觉方向：以明亮、清晰的方案 1 为主体，吸收方案 2 的市场数据秩序和方案 3 的投资逻辑结构。

布局从左到右：

- **176 px 左侧导航：** 品牌、五个一级导航、底部市场状态。
- **主内容区：** 顶部搜索和市场脉冲；下方为“今天值得关注”。
- **约 360 px 右侧栏：** 本周事件和投资逻辑检查。

“今天值得关注”默认显示三条信号，其中一条展开。展开态包含：

- 股票名称、价格、涨跌与信号强度。
- 一张克制的短周期价格图和相对成交量。
- 三条可解释的关注原因。
- 最多三条相关事件。
- 主动作“研究 {代码}”。
- 次动作“加入观察”。

右侧“投资逻辑检查”固定使用四行结构：

- 核心判断
- 支撑证据
- 主要风险
- 验证条件

每行显示最新变化或即将到期状态，点击后进入该股票的投资逻辑。

### 8.2 “发现”页

- 左侧为筛选条件区，支持基本面、估值、成长、质量、动量和事件六类条件。
- 主区为可排序结果表，并支持在表格、简图和热力图之间切换。
- 用户可以保存筛选器，但首版不支持脚本化条件。
- 每个筛选条件显示定义、数据周期和缺失值处理方式。

### 8.3 “自选”页

- 支持创建分组与拖动排序。
- 默认列为价格、当日涨跌、五日变化、估值状态、下一事件和逻辑状态。
- 点击行进入股票研究页；展开行可快速查看迷你图和最新信号。
- 用户可为整个分组设置统一条件提醒。

### 8.4 股票研究页

研究页采用方案 3 的连续研究画布，不把每项数据做成独立卡片。

- 上半区：长期价格图、关键财务趋势和估值区间。
- 下半区：最新证据时间线、同业比较和事件。
- 固定右栏：投资逻辑，包括判断、证据、风险和验证条件。
- “更新投资逻辑”是主动作，“加入模拟组合”是次动作。
- 所有证据包含来源、发布日期和财务周期。

### 8.5 “组合”页

- 顶部显示模拟组合总值、累计收益、当日变化和基准差异。
- 主区显示收益曲线、持仓列表、行业暴露和集中度。
- 风险提示只描述事实，例如“单一持仓占比 31%”，不输出买卖建议。
- 模拟买入或卖出必须关联一条已有投资逻辑，或在操作时新建。

### 8.6 “日志”页

- 按时间显示投资逻辑版本、模拟交易、提醒触发和复盘。
- 支持按股票、组合、结果和标签筛选。
- 每条记录不可静默覆盖；修改会创建新版本。
- 用户可比较两个版本之间的判断、证据、风险和条件变化。

## 9. 视觉系统

### 9.1 方向

视觉关键词：明亮、冷静、可信、可读、专业但不压迫。

- 页面使用统一底色，不把整个应用放进居中卡片。
- 优先依靠间距、对齐、字号和分隔线组织信息。
- 只有真正独立的对象使用容器；禁止卡片嵌套。
- 行情涨跌颜色只表达变化，不承担主操作或品牌含义。

### 9.2 色彩

| 用途 | 色值 |
| --- | --- |
| 页面背景 | `#F8FAFC` |
| 主表面 | `#FFFFFF` |
| 主文字 | `#101828` |
| 次文字 | `#667085` |
| 分隔线 | `#E4E7EC` |
| 品牌/主动作 | `#155EEF` |
| 品牌悬停 | `#004EEB` |
| 上涨/正向 | `#039855` |
| 下跌/风险 | `#D92D20` |
| 待验证 | `#DC6803` |

### 9.3 字体与密度

- 中文：`Noto Sans SC`。
- 数字与拉丁字符：`Inter`，启用等宽数字。
- 正文默认 14–16 px，辅助文字不小于 12 px。
- 页面标题 28–32 px，区块标题 18–22 px。
- 使用 4 px 基础间距系统；常用间距为 8、12、16、24、32 px。
- 圆角以 6–8 px 为主；阴影仅用于弹层和临时浮层。

### 9.4 图表

- 默认最多同时显示两条数据序列。
- 网格线和坐标轴保持低对比度。
- 图例必须写明单位、频率和数据周期。
- 颜色不能是唯一区分手段，同时使用标签、线型或符号。
- 图表空白、加载、部分数据和错误状态必须有明确文案。

## 10. 功能边界与模块

系统按职责拆分为以下模块：

| 模块 | 职责 | 依赖 |
| --- | --- | --- |
| 市场数据 | 行情、K 线、指数、公司事件和财务数据归一化 | 外部数据供应商 |
| 股票目录 | 代码、交易所、公司和行业标识 | 市场数据 |
| 信号引擎 | 根据用户自选与透明规则生成可解释变化 | 市场数据、自选 |
| 研究工作区 | 展示图表、财务、估值、同业与事件 | 市场数据、股票目录 |
| 投资逻辑 | 保存判断、证据、风险、条件与版本 | 用户、股票目录 |
| 模拟组合 | 模拟交易、持仓、收益与风险暴露 | 市场数据、投资逻辑 |
| 提醒 | 价格、事件和验证条件触发 | 市场数据、投资逻辑 |
| 日志 | 汇总逻辑版本、模拟交易、提醒与复盘 | 以上业务模块 |

模块通过稳定的数据接口通信。UI 不直接依赖具体数据供应商字段，供应商切换由市场数据模块消化。

## 11. 核心数据对象

- **Instrument：** 股票代码、交易所、公司、币种和行业。
- **MarketSnapshot：** 价格、涨跌、成交量、时间戳和延迟状态。
- **FinancialFact：** 指标、数值、单位、财务周期、来源和发布日期。
- **Signal：** 类型、股票、摘要、证据、强度、生成时间和规则版本。
- **Watchlist：** 名称、股票集合、排序和提醒规则。
- **Thesis：** 核心判断、支撑证据、主要风险、验证条件、状态和版本。
- **PaperPortfolio：** 组合、现金、基准和持仓。
- **PaperTransaction：** 股票、方向、数量、模拟价格、时间和关联逻辑。
- **Alert：** 触发条件、状态、到期时间和关联对象。
- **JournalEntry：** 类型、时间、正文和关联的股票、逻辑或交易。

## 12. 数据流

1. 数据接入层拉取并归一化行情、财务和事件。
2. 缓存层记录更新时间、来源与延迟状态。
3. 信号引擎只对用户自选和已保存筛选器执行透明规则。
4. API 向前端返回领域对象，不暴露供应商专用字段。
5. 前端通过服务端状态缓存读取市场数据，通过用户状态保存自选、逻辑和组合。
6. 提醒服务监听新数据并生成站内通知。
7. 所有投资逻辑与模拟交易写入不可变日志，修改产生新版本。

## 13. 加载、空白与异常处理

### 13.1 数据新鲜度

- 每个行情区域显示“实时、延迟 N 分钟、收盘或模拟”。
- 每个财务指标显示报告期和来源。
- 数据超过预设时效时保留最后可用值，并明显标记“数据可能过期”。

### 13.2 部分失败

- 单个模块失败不阻断整个页面。
- 图表失败时仍展示价格摘要、研究逻辑和其他可用数据。
- 财务数据缺失时说明缺失范围，不以零替代。
- 外部数据源限流时提示稍后重试，并显示上次更新时间。

### 13.3 用户操作

- 保存投资逻辑失败时保留本地草稿并提供重试。
- 模拟交易必须二次确认股票、数量、价格和关联逻辑。
- 删除自选分组或投资逻辑使用可恢复的软删除。
- 提醒失效或到期时说明原因并允许重新启用。

## 14. 可访问性与适配

- 达到 WCAG 2.2 AA 的文字对比度和键盘可操作性。
- 所有交互控件有清晰焦点样式和可读标签。
- 表格支持键盘浏览，图表提供同等信息的文字摘要。
- 不只用红绿表达涨跌。
- 首版重点支持 1280–1920 px 桌面宽度。
- 1024–1279 px 自动收起左侧导航并将右栏变为抽屉。
- 小于 1024 px 提供只读的核心查看体验，不承诺完整研究编辑能力。

## 15. 合规与信任

- 页面明确标注“仅供研究与模拟，不构成投资建议”。
- 模拟收益不与真实收益混淆。
- 不使用“稳赚、最佳买点、强烈买入”等确定性语言。
- AI 生成内容必须标记，并展示所引用的数据和来源。
- 用户隐私数据不用于公开排名或未经授权的模型训练。

## 16. 验收与测试

### 16.1 核心体验验收

- 用户可以从首页信号一次点击进入对应股票研究页。
- 用户可以创建包含四个必需部分的投资逻辑。
- 用户可以将投资逻辑关联到模拟交易和验证提醒。
- 提醒触发后可以进入复盘并产生新的逻辑版本。
- 任意市场数据都能追溯时间、状态和来源。

### 16.2 测试范围

- 单元测试：信号规则、收益计算、验证条件和数据归一化。
- 集成测试：市场数据到研究页、逻辑到提醒、交易到日志。
- 端到端测试：每日检查、创建逻辑、模拟建仓和事件后复盘。
- 视觉测试：1440 × 1024、1280 × 800 和 1024 × 768。
- 可访问性测试：键盘流程、焦点顺序、对比度和屏幕阅读器标签。
- 异常测试：行情延迟、财务缺失、供应商限流、保存失败和断网恢复。

## 17. 实施顺序

1. 应用框架、导航、视觉令牌和模拟数据层。
2. “今日”首页与股票搜索。
3. 股票研究页与财务/估值模块。
4. 自选列表与筛选器。
5. 投资逻辑、版本和决策日志。
6. 模拟组合与收益计算。
7. 提醒与事件后复盘。
8. 数据源替换、性能、可访问性和错误状态完善。

首个可验证里程碑是：使用可信模拟数据完成“首页信号 → 股票研究 → 创建投资逻辑 → 加入模拟组合”的完整闭环。
