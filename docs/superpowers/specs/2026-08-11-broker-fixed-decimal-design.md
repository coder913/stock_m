# 券商金额定点精度设计

## 目标

消除 Alpaca 成交活动进入 Paper 账本时的 JavaScript 浮点乘法，使数量、价格、成交金额、账本回放与对账差额在服务端始终使用明确的定点表示。Alpaca 官方支持 fractional quantity 最多 9 位小数，因此数量使用 9 位、金额与价格使用 8 位。

## Decimal 规则

- 输入是普通十进制字符串，可带负号，整数部分必须存在。
- 数量内部缩放 `1000000000`，金额与价格缩放 `100000000`，均使用 BigInt。
- 输出固定为相应位数，避免科学计数法与平台相关格式。
- 成交乘法将九位数量与八位价格相乘，再按“绝对值五入”舍入为八位金额；正负值采用对称规则。
- 非法格式、超出对应精度和负的成交数量/价格直接抛出明确错误，不静默截断。

## 活动映射

- 若 Alpaca 活动已提供 `amount`，保留原始 Decimal 字符串交给数据库约束。
- 若 FILL 缺少 `amount`，使用 BigInt 定点数量乘价格。
- buy 生成负金额，sell 生成正金额；先取乘积绝对值，避免异常负输入改变现金方向。
- 未知活动仍只保留 provenance，不虚构金额。

## 账本复用

`brokerLedger` 改用相同 Decimal 解析、格式化和减法函数。券商数量列通过新迁移扩展为 `numeric(29,9)`，金额与价格仍为 `numeric(28,8)`；入口计算、数据库、回放与 drift 差额共享同一精度规则。

订单预览已有独立的领域错误码与正数校验，本次不改变其 API 错误语义；后续可在保持错误映射的前提下复用底层工具。

## 测试

- `0.1 × 0.2` 不出现二进制浮点尾差。
- 超过 JavaScript 安全整数范围的数量仍保留精确金额。
- 半个最小单位按规则舍入。
- buy/sell 符号正确。
- 非法或超出 8 位的小数被拒绝。
- 现有账本回放和 drift 差额测试保持通过。
